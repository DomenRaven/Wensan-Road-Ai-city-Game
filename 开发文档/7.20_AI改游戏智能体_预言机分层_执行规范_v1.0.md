## 2. 实现约束

### 2.1 L1（`assert_evidence_wired`）

1. 拆分 `wired_by`：支持 `list[str]`、`A|B`、逗号分隔；**不**把含 `/` 的散文当函数名。  
2. 对每个候选 caller：取函数体，查 `symbol` 引用/调用；任一命中即过。  
3. 间接：若直接 caller 未命中，沿同文件内「caller 调用的下一函数」最多再查 2 层（实现宜保守、可单测）。  
4. `symbol` 含空格或 `func`/`var` 关键字拼盘 → 立即错误：「请拆成多条 evidence」。  
5. 继续 strip 注释后再判引用（防注释刷分）。

### 2.2 L2（新建 `assert_presentation_predicates` 或等价名）

1. 输入：`workspace_root` + `goals: list[str]` + 可选 `user_text`。  
2. 仅当触发器命中才收集谓词；结果并入 `run_done_gates` errors。  
3. **进度条族**：扫 `**/*.tscn` 找 ProgressBar/TextureProgressBar；扫本轮或全 workspace `*.gd` 找 `.value` / `.ratio` / `set_value` 等写入；写入须出现在 `_process`/`_physics_process` 体或 Timer 回调（可与 L1 共用 `_extract_func_body`）。  
4. **图标族**：goals 含图标/命数显示等 → 找名称含 `Life`/`Icon`/`Lives` 的 TextureRect（启发式宽进严出）；`texture` 属性非空 **或** 脚本对图标节点设置 texture/占位（实现选一种可单测策略，写入施工注释）。  
5. 错误文案须可行动，例如：`L2 图标可见失败：LifeIcon1 无 texture 且无占位路径`。

### 2.3 触发词（初版，可调）

- 进度：`进度条` `冷却条` `充能条` `ProgressBar`  
- 图标：`图标` `命数图标` `血量图标` `生命图标` `LivesDisplay`  

无命中 → 跳过 L2。禁止加 Boss/飞机专用词。

### 2.4 回灌

`game_agent` 在 self_check/done 失败时，把 L1/L2 `gate_errors` 全文进入 observation / 下一轮 tip（已有路径则复用）。禁止只塞 summary。

### 2.5 Tip

肯定式、品类通用：提醒 UI 类 goals 须节点可见/驱动，**不要**再写「禁止某某」窄句；保持 `test_hf11_llm_facing_prompts_are_affirmative` 绿。
