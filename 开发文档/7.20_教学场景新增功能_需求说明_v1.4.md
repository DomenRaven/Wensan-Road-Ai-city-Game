## 0. 一句话

服务器部署下，入口可选**游客**或**登录账号**两线并行；登录用户跳过「你的名字是？」、用注册昵称组作品名。所有新增能力**只改临时工作区、严禁动模板源码**。学生可阅读真实工作区与每轮 Diff、打星并注入下一轮 LLM；学情记录含用户原话与智能体**完整长回复**等，长期保存供汇总。目标约 **70** 人在线；试玩按 **S2-路B + S4**（见 §8.3）。

## 1. 背景与问题

| 现状（截至 7.19 / 产品 v1.2） | 教学缺口 |
|------------------------------|----------|
| B5 代码剧场以演示高亮为主，非完整真实仓库浏览 | 学生难以「像打开项目一样」阅读真代码 |
| B6 证书本机 PNG；B7 左侧代码随玩法高亮 | 证书后缺少正式「查看游戏代码」入口页 |
| nl-patch 后仅有摘要 / sandbox 文件名列表 | 看不到相对改前版本的行级 Diff |
| 无星级评价 → 下一轮 LLM 无结构化用户满意度 | 智能体难对齐「满不满意」 |
| 匿名 `session_id`，`max_sessions` 默认 10；workspace 随 release 销毁 | 无法多班账号隔离，也无法支撑约 70 人并发 |
| Learned Skill / 日榜等有部分落盘，但无完整学情流水 | 无法管理员汇总对话、评价、问卷做教研迭代 |
| 无「结课心得」类问卷入口 | 缺反思沉淀与长期结构化记录 |

## 2. 目标与非目标

### 2.1 目标（本需求包必须覆盖）

1. **真实代码可读**：剧场完成且证书保存成功后，可进入美观的代码浏览页，读当前会话工作区真实文件。  
2. **改动可对照**：每次与 AI 对话落地后，可看「本轮后工作区」vs「本轮前快照」的行级 Diff，并带教学向注释。  
3. **评价闭环**：每轮改游戏后 1～5 星评价；下一轮对话默认结构化注入上轮评价。  
4. **两线入口 + 隔离**：初始页游客 ∥ 登录；开放自助注册；登录用户按账号隔离；约 **70** 在线（§8.3）。  
5. **长期学情库**：用户原话、智能体**完整长回复**、评价、问卷等持久化（**已确认 SQLite**），**不随登出 / workspace 释放删除**。  
6. **问卷入口**：主页面可填「我与 AI 的协作」类反思问卷，长期保存、可汇总。

### 2.2 非目标（本需求包不做或另立项）

| 不做 | 说明 |
|------|------|
| 改 `templates/{genre}/core/**` 玩法冻结源 | **RL-1/RL-2 已拍板强化**：教学增量同样严禁 |
| 邀请码 / 教师审批 / 批量导入注册 | **已否决**；开放自助注册（§F4） |
| 恢复 catalog express / 削弱门禁 | 教学可见性 ≠ 放宽 Agent 安全 |
| 运行时自动爬全网写 Skill | 仍锁定 |
| 联机对战、内购、广告、商城、云存档玩法 | 产品禁区不变 |
| 手机扫码带走证书公网链路 | 仍见展厅部署缺口；与本包正交 |
| 把 B5 剧场伪代码「演成」真 Diff | 剧场可保留演示感；真代码以 F1/F2 页为准 |
| 学生互看他人工作区 / 公开心得墙（首版） | 问卷可先仅管理员可见；公开墙另议（§11） |
| 在无学生机 Godot 时硬承诺 70 路同开试玩窗 | 见 §8.3 方案对比与推荐 |

## 3. 产品形态：游客 ∥ 登录 两线并行（已拍板）

### 3.1 初始页（新建）

服务器/Kiosk 打开后进入 **初始选择页**（新建页面，非直接进 B1）：

| 选项 | 行为 |
|------|------|
| **游客模式** | 不注册；沿用现有匿名 `session` 动线（含「你的名字是？」→ 游戏起名 → B3…）；学情可记匿名 `guest_session_id`（能记则记，不强制账号） |
| **登录模式** | 注册 / 登录成功后进入 B 链；**跳过「你的名字是？」**；作品名用注册昵称规则（§3.3） |

两线**并行长期存在**，不是「仅教学模式强制登录」。管理员账号走登录后进汇总台。

### 3.2 动线对比

```text
【游客】
  初始页 → 游客 → B1 选游戏 → B2「你的名字是？」+ 游戏起名 → B3…B7
  → F1/F2/F3/F6（问卷可选匿名或提示登录以便汇总）

【登录】
  初始页 → 注册/登录 → B1 选游戏 → 【跳过你的名字】→（游戏起名见 §3.3）→ B3…B7
  → F1/F2/F3/F6（学情绑定 user_id）→ 登出
  （workspace 可释放；学情库保留）
```

### 3.3 登录模式命名规则（已拍板）

| ID | 需求 | 验收 |
|----|------|------|
| F4-N1 | 登录用户选好品类后，**不再出现**「你的名字是？」（现 B2 创作者名子步） | UI 无该步；`creator_name` 自动取注册昵称 |
| F4-N2 | 注册时必填 **昵称** `nickname`（展示名）+ **用户名** `username`（登录唯一键）+ 密码 | 字段校验见 F4.2 |
| F4-N3 | 默认作品展示名格式 | `{nickname}（{username}）的{品类中文名}游戏`；品类中文名取自现网 `config/kiosk_edu_spec.json` → `genre_display_names`（例：shmup → **街机飞机射击** → `小明（xiaoming）的街机飞机射击游戏`） |
| F4-N4 | 与现网文案对齐 | 页眉/证书/揭幕等凡使用「创作者 + 作品名」处，登录模式用 F4-N3；不得再向用户索要创作者名 |
| F4-N5 | 「给游戏起个名字」子步 | **已确认默认**：保留该子步；默认填入 F4-N3 全文，允许改游戏名；创作者名始终锁定为昵称 |

游客模式命名逻辑**保持现状**（先问你的名字，再起游戏名）。

## 4. 功能需求明细

> 各功能确认状态见 **§0.2.2**。本章为展开规格与验收条目。

### F1 · 证书后「查看游戏代码」（真实工作区浏览器阅读）

#### F1.1 用户故事

> 作为学生，在代码剧场完成并且证书保存成功后，我希望点一个按钮进入专门页面，像打开项目一样浏览**当前临时工作区里的真实文件与真实内容**，方便阅读和切换文件，并看到帮助理解的注释。

#### F1.2 触发条件（须同时满足）

| ID | 条件 | 说明 |
|----|------|------|
| F1-T1 | B5 代码剧场阶段已成功完成 | `generate` / 工作区已就绪，存在有效 `workspace` |
| F1-T2 | 证书 **保存成功** 至少一次 | 与现有「本机保存 PNG」成功回调对齐；仅「闪现证书」未保存 **不** 解锁 |
| F1-T3 | 会话仍有效且工作区未销毁 | release 后按钮禁用或提示「工作区已清理」 |

入口位置（UI）：

### F2 · 每轮 AI 对话后的真实代码 + 对照 Diff

#### F2.1 用户故事

> 作为学生，每次和 AI 改游戏对话结束后，我希望看到临时工作区里的真实代码，并能和**改之前**对照；新增/修改用荧光绿高亮，删除用荧光红+斜体，最好还有注释说明 AI 动了什么——就像在 Cursor 里看完一次修改的 Diff。

#### F2.2 触发与入口

| ID | 需求 | 验收 |
|----|------|------|
| F2-T1 | 每一次 nl-patch / Agent 回合 **结束**（成功、partial、失败回滚均须有结果态）后，对话框内出现 **「查看本轮代码改动」** | 按钮可见；失败回滚时展示「未保留改动」说明 + 仍可看尝试轨迹（见 F2-D5） |
| F2-T2 | 不强制打断打分（F3）；建议顺序：**摘要 → 看 Diff（可跳过）→ 打星（可稍后）→ 重开试玩** | 顺序可配置，但三项入口均可达 |
| F2-T3 | 历史回合可回看 | 对话气泡旁保留「看该轮 Diff」；至少保留本会话内最近 K 轮（建议 K≥10）元数据 |

#### F2.3 Diff 语义（核心）

| ID | 需求 | 验收 |
|----|------|------|
| F2-D1 | **对照基线** = 本轮 Agent **开始前** 工作区快照 | 非模板原始包；多轮时第 N 轮对照第 N 轮开始前 |
| F2-D2 | **对照目标** = 本轮结束后磁盘上的工作区（若门禁失败并回滚，则为回滚后状态，并标注 `rolled_back=true`） | 与真实文件一致 |
| F2-D3 | **新增/修改行**：荧光绿色背景（或左侧色条+绿底），清晰可读 | 类 Cursor/GitHub diff 的 add 样式 |
| F2-D4 | **删除行**：荧光红色背景 + **斜体** | 类 Cursor/GitHub diff 的 del 样式；删除行仍显示旧内容 |
| F2-D5 | 展示维度 | ① 文件列表（仅本轮有变更的文件，可切换「全部文件」）② 单文件 unified 或 side-by-side Diff ③ 无变更时明确文案 |
| F2-D6 | 同时可切换 **「改后全文」** 与 **「对照 Diff」** | 满足「看真实代码」+「看动了哪些」 |
| F2-D7 | **注释** | 每轮总述优先取本轮 **`agent_reply_full`（或同等 UI 长文）** / goals 落地说明；每个变更文件 1～3 句「为什么改」；hunk 旁注不另调 LLM（OQ-6） |
| F2-D8 | 只读、安全同 F1 | 仅本账号本会话；禁止写盘；Diff 涉及的路径须在可读白名单或快照库内 |

#### F2.4 快照与存储（实现约束写入需求）

| ID | 需求 | 说明 |
|----|------|------|
| F2-S1 | 每轮开始前对将可能被改的树做 **before 快照**（或内容寻址 blob） | 至少覆盖 Agent 可写范围：`config/**`、`core/**`、`scenes/**`、`ai_sandbox/**` 等 |
| F2-S2 | 每轮结束后固化 **after 清单 + 统一 Diff 元数据** | 写入**长期学情库**（F5），不只放在即将销毁的 workspace |
| F2-S3 | workspace `release` 后 | 浏览器仍可从学情库阅读**该轮 Diff 与关键文件文本快照**（教学回看）；实时工作区树（F1）在无 workspace 时不可用 |
| F2-S4 | 体积控制 | 文本文件快照；二进制不入 Diff；单轮 Diff 存储上限与淘汰策略可配置（但学情索引与评价不删，见 F5） |

#### F2.5 UI 观感

- 深色或浅色代码主题二选一（教学机房可读优先，建议提供切换）。  
- Diff 颜色须满足可访问性：不只靠颜色，删除行保留删除线或「−」前缀，新增行「+」前缀。  
- 触控：文件 Tab/列表可点；双栏在窄屏可上下堆叠。

### F3 · 每轮改游戏后的星级评价 + 注入下一轮 LLM

#### F3.1 用户故事

> 作为学生，每次 AI 改完游戏后，我可以用 1～5 颗星表达满不满意；下一轮我再说话时，系统应把我上轮的评价结构化告诉 AI，让它更懂我的想法。

#### F3.2 评分量表（固定文案）

| 星级 | 展示文案 | `score` |
|------|----------|---------|
| ★☆☆☆☆ | 非常不满意 | 1 |
| ★★☆☆☆ | 比较不满意 | 2 |
| ★★★☆☆ | 一般般 | 3 |
| ★★★★☆ | 比较满意 | 4 |
| ★★★★★ | 非常满意 | 5 |

| ID | 需求 | 验收 |
|----|------|------|
| F3-R1 | 鼠标/触控点击星星选择 1～5 | 悬停预览、点击确认；可改选后提交 |
| F3-R2 | 星旁同步显示对应中文档位 | 与上表一致，不可自定义档位文案（首版） |
| F3-R3 | 出现时机 | 本轮 Agent 结果已展示后（含 partial）；与「查看本轮代码改动」同区 |
| F3-R4 | 可选简短文字反馈 | 建议最多 200 字；可不填 |
| F3-R5 | 提交后状态 | 显示「已记录，谢谢」；本轮不可重复刷分（可「修改评价」覆盖 1 次或 N 次，需审计留痕） |
| F3-R6 | 跳过 | 允许暂不评价；**未评价不得伪造分数注入 LLM** |

#### F3.3 注入下一轮 LLM（结构化）

当用户发起**新一轮** nl-patch 时，若存在「上一轮已提交评价」，后端必须把结构化块注入 Agent 上下文（系统侧或工具可读上下文，**不要**伪装成用户原话）。

**建议注入 JSON 形态（逻辑字段，实现可微调键名）**：

```json
{
  "previous_turn_user_rating": {
    "score": 4,
    "label": "比较满意",
    "comment": "跳得更高了，但还想要粒子特效",
    "rated_turn_id": "trn_xxx",
    "rated_user_request_summary": "让主角跳得更高",
    "rated_agent_outcome": "partial|success|failed",
    "gate_passed": true
  }
}
```

| ID | 需求 | 验收 |
|----|------|------|
| F3-I1 | 默认开启注入 | 游客/登录凡有上轮已提交评价时均注入；无需用户再勾选 |
| F3-I2 | 注入内容含分数、档位文案、可选评论、上轮结果态 | 单测或探针可断言 prompt/context 含该块 |
| F3-I3 | Agent 行为期望（软） | 低分（1–2）应优先澄清不满点/复读盘再改；高分可在摘要中简短确认方向 |
| F3-I4 | 不评价则不注入 | 避免「默认 5 星」等幻觉 |
| F3-I5 | 评价写入 F5 学情库 | 与 turn 绑定，长期可查 |

### F5 · 学情与运营数据结构化长期保存

#### F5.1 用户故事

> 作为管理员/教研，我希望每个学生使用智能体改游戏时的**发送内容、智能体完整长回复、每次评价、问卷**都被结构化记下来且长期保存，不因登出或临时工作区释放而丢失，便于汇总和持续更新智能体。

#### F5.2 必须持久化的实体

| 实体 | 关键字段（逻辑） | 生命周期 |
|------|------------------|----------|
| `User` | id, username, nickname, role, class_label, created_at | 长期 |
| `PlaySession` | id, user_id \| guest_key, genre, display_name, creator_name, mode(`guest`/`login`), created_at, ended_at, workspace_key | 元数据长期；磁盘 workspace 可删 |
| `AgentTurn` | 见下表「回合正文」 | **长期** |
| `AgentTurnDiff` | turn_id, files[]（path, change_type, diff_text 或 blob_ref）, before_ref, after_ref | **长期**（可冷存储） |
| `TurnRating` | turn_id, user_id, score 1–5, label, comment, created_at, updated_at | **长期** |
| `SurveyResponse` | 见 F6 | **长期** |
| `AuditLog` | admin 导出/登录失败等（建议） | 长期 |

##### 回合正文（已拍板：智能体回复 = 每轮完整长回复）

| 字段 | 要求 |
|------|------|
| `user_text` | 学生本轮发送的完整原文 |
| `agent_reply_full` | **学生在对话 UI 中看到的本轮完整长回复**（见 F5-L2 拼装；**不是**只存短 `summary`） |
| `agent_summary` | 可选：对应 API 字段 `summary`（门禁/内部）；**汇总导出默认以 `agent_reply_full` 为准** |
| `how_to_play` | 建议结构化另存（现网 API 已有列表字段）；同时可拼进 `agent_reply_full` |
| `provider` / `gate_passed` / `partial` / `rolled_back` / `sandbox_files` / `goals` / 时间与耗时 | 对齐现网 `NlPatchResponse` 语义 |

| ID | 需求 | 验收 |
|----|------|------|
| F5-L1 | 学情「智能体回复」= **完整长回复** | 管理端打开某回合，可见与学生气泡一致（或等价全文），不得仅有「已完成」类短句 |
| F5-L2 | **拼装规则（对齐现网 UI）** | 现网对话框主文案为 `message \|\| summary`，其下另渲染 `how_to_play[]`。落库时：`agent_reply_full` = 主文案 +（若有）试玩步骤列表的规范拼接文本，保证导出可读全文与课堂所见一致 |
| F5-L3 | 长度 | 支持至少数 KB～数十 KB 中文；超大截断须标记 `truncated=true` 并尽量保守 |

#### F5.3 学情库选型（按本仓库现状 · **已确认 SQLite**）

**现状对齐**：

- 会话：`SessionStore` = Redis（可选）/ 内存；`max_sessions` 默认 10。  
- 能力沉淀：`data/learned_skills/**` = **JSONL + 目录文件**（`index.jsonl`、experiences、snippets）。  
- 本局日志：workspace 内 `.session_ai_log.jsonl`（随 release 可丢）。  
- **无**现成 ORM/PostgreSQL 依赖。

| 方案 | 做法 | 优势 | 风险 | 结论 |
|------|------|------|------|------|
| A. 纯 JSONL 目录 | 仿 `learned_skills`，`data/learning_analytics/*.jsonl` | 与现网一致、零新依赖、易备份拷贝 | 70 人并发追加+按用户/时间筛选/导出吃力；缺事务 | 适合附录冷归档，**不适合唯一主库** |
| B. **SQLite 主库** | `data/learning_analytics/learning.db` + 大文本/Diff blob 可外置文件 | 单文件、部署简单；SQL 筛选/导出；与单机/单服务器校园部署匹配；Python 标准库即可 | 多进程写要 WAL+单写者约定；未来多机 API 水平扩展需迁移 | **已确认（首版）** |
| C. PostgreSQL | 独立 DB 服务 | 真·多连接并发与多机扩展 | 运维重、展厅/瘦身包不习惯；超出现网栈 | 仅当确认多机 API 集群再上 |
| D. 全放 Redis | 会话式 KV | 快 | **不满足长期保存**；重启/淘汰丢数据 | **否决**作学情主存 |

**落地（已确认：B 为主，A 可作冷备导出）**：

1. **主存**：SQLite（WAL），表结构对应 User / PlaySession / AgentTurn（含 `agent_reply_full`）/ TurnRating / SurveyResponse；Diff 大文本可 `blobs/{turn_id}/…` 文件，DB 只存路径与哈希。  
2. **与 Learned Skill 分离**：路径建议 `data/learning_analytics/`，勿写入 `data/learned_skills/`（后者仍守 G8 有效 harvest）。  
3. **游客**：`user_id` 可空，用 `guest_key`（session 级）关联；登录用户强制 `user_id`。  
4. **并发写**：后端对学情写入串行化（队列或连接 `check_same_thread`+锁）；nl-patch 主路径可先写内存再刷盘，但 **下一轮评价注入前评价行必须可读**。  
5. **备份**：部署手册要求定期拷贝 `learning.db` + `blobs/`；与 `workspace/` 分离。

> 若日后单机 SQLite 成为瓶颈（少见，70 人学情写入远小于 LLM），再迁移 PostgreSQL；表结构按 SQL 抽象即可。

#### F5.4 硬性规则

| ID | 需求 | 验收 |
|----|------|------|
| F5-R1 | `POST /release`、登出、超时清理 workspace **不得删除**上述学情实体 | 自动化测试：release 后 DB 仍在 |
| F5-R2 | 记录在 Agent 回合结束时同步写入（评价/问卷在提交时写入） | 允许短延迟，但进程崩溃应尽量可恢复 |
| F5-R3 | 结构化 | JSON/表字段可查询；长回复进专用字段/列，禁止「只有无法解析的一大坨」 |
| F5-R4 | 管理员汇总 | 按班级/时间筛选；导出 CSV/JSON（长回复列完整或附件）；单用户时间线：用户话 → **完整回复** → Diff → 评分 → 问卷 |
| F5-R5 | 隐私 | 学生端只看自己的；admin 看全部；游客数据不串到他人账号 |
| F5-R6 | 备份 | 见 §F5.3；与 workspace 目录分离 |

#### F5.5 管理员最小界面（首版可简易）

- 登录为 admin →「数据汇总」：用户数、回合数、平均星级、问卷回收数。  
- 下钻：用户话 / **完整长回复** / 星级 / Diff 有无。  
- 导出。

> 精美 BI 大屏不在首版范围。

### F6 · 主页面调查问卷（协作心得）

#### F6.1 用户故事

> 作为学生，我在主页面能找到调查问卷入口，按提示写下与 AI 协作的真实感受；提交后长期保存，供教学汇总。内容结构参考[活字编程结课心得页](https://zwy.alimq.com/huozi/reflection.html)。

#### F6.2 入口

| ID | 需求 | 验收 |
|----|------|------|
| F6-E1 | B 链教育主页面（开馆/选品类附近）增加 **「协作心得 / 调查问卷」** 入口 | 显式按钮或卡片，不藏进高级菜单 |
| F6-E2 | 登录用户提交绑定 `user_id`；游客可填，绑定 `guest_key`（汇总时标为游客） | 两线均可提交 |
| F6-E3 | 填写中可保存草稿（建议）；正式提交有确认 | 提交成功明确反馈 |

#### F6.3 问卷题项（首版结构化字段）

对齐参考页「可以聊聊这几点」，并结合本工坊语境微调文案（不必全答，但字段预留；UI 标明选填/必填策略见下）。

| 字段 key | 题干（展示文案） | 必填 | 类型 |
|----------|------------------|------|------|
| `one_liner` | **一句话感受**：如果只用一句话形容这次和 AI 一起改游戏，你会怎么说？ | 建议必填 | text ≤200 |
| `division_of_labor` | **你们怎么分工**：哪些事你拿主意、哪些交给 AI？你更像它的老板、搭档，还是学生？ | 选填 | text ≤1000 |
| `frustration_or_surprise` | **最受挫 / 最惊喜的一次**：讲一个具体瞬间——它把你气笑了，或给了你完全没想到的东西。当时发生了什么？ | 选填 | text ≤2000 |
| `tip_for_prompting` | **你摸出的一个小技巧**：怎么提问它才听得懂、怎么让它别跑偏、怎么让它帮你验证？ | 选填 | text ≤1000 |
| `human_irreplaceable` | **人该做什么**：AI 这么强，你觉得「人」不可替代的地方在哪？这次对「自己的价值」有没有新想法？ | 选填 | text ≤1000 |
| `advice_to_next` | **给下一个你**：如果下一批同学明天开始用这个工坊，你最想提醒一句什么？ | 选填 | text ≤500 |
| `is_public` | **是否愿意公开给同学阅读**（心得墙，二期） | 选填，默认「不公开」 | enum: `public` / `private` |
| `free_note` | 其他想说的 | 选填 | text ≤2000 |

页头说明文案（须出现，可改编）：

- 不聊分数，聊真实感受；真诚、具体；**请写你自己的体会，不要让 AI 代写一篇不像你的漂亮文章**。  
- 价值点提示可引用课程理念（意图与表达、提问方式、人的判断、经验沉淀、AI 边界）——语气亲切，勿说教过长。

#### F6.4 存储与汇总

| ID | 需求 | 验收 |
|----|------|------|
| F6-S1 | 提交写入 F5 `SurveyResponse`，含 `user_id`、时间戳、题项 JSON、工坊语境元数据（可选 `genre`/`session_id`） | release 后仍在 |
| F6-S2 | 允许同一用户多次提交 | 每次新版本；列表可看历史；「最新一份」标记 |

| F6-S4 | 首版不做公开心得墙 | `is_public` 先入库；公开展示另期 |

## 8. 非功能需求

### 8.1 性能与容量

- 代码树首屏 < 3s（局域网、工作区文件数≤阈值时）。  
- Diff 页普通回合（变更文件 ≤20、单文件 ≤3000 行）可交互打开。  
- 学情写入不得显著拖慢 nl-patch 主路径（可异步落库，但评价注入下一轮前必须已可读）。

### 8.2 安全

- 密码哈希（如 Argon2/bcrypt）；防暴力登录节流。  
- 路径穿越、Session 猜解、越权读 Diff 为 P0 缺陷。  
- XSS：代码展示必须转义；Markdown 注释需消毒。

### 8.3 服务器场景「约 70 并发」方案对比与推荐（已展开）

先拆指标（勿混为一谈）：

| 指标 | 含义 | 难度 |
|------|------|------|
| **C70-Web** | ~70 人同时打开站点、选品类、看代码/Diff、填问卷、维持会话 | 中（API + Redis/会话 + 静态资源） |
| **C70-Agent** | ~70 人**同时**跑 nl-patch / LLM Agent | 高（LLM 配额、CPU、墙钟 360s、磁盘写 workspace） |
| **C70-Play** | ~70 人**同时**拉起 Godot 试玩窗 | 很高（现网 = 本机进程 + 全屏置顶；服务器集中拉起几乎不可行） |

#### 方案表

| 方案 | 架构要点 | 优势 | 风险 / 代价 | 适用 |
|------|----------|------|-------------|------|
| **S1. 单服务器包办一切**（API+Kiosk+全员 Godot 都在一台） | 一台 Windows/Linux 跑 FastAPI；试玩也在该机 `godot_launcher` | 部署最简单、与现展厅包接近 | **C70-Play 基本不可达**（几十个 Godot 窗会打爆 GPU/桌面会话）；Agent 同时打满易拖死 API | 仅小班（≤10）或演示 |
| **S2. 中央 API + 学生机本地 Godot** | 服务器：API / Kiosk / Redis / 学情 / workspace；学生机装 Godot 4.6。**路 B（已选）**：共享盘映射后本机打开本人目录；**路 A（不做）**：打包下载再玩 | C70-Web 可达；Play 分散到学生机 | 需 IT 镜像、映射盘、权限；现网 `play/launch` 须改为教学部署下的本地启动 | **校园机房已确认（路 B）** |
| **S3. 中央 API + 试玩槽位排队** | 服务器只允 N 个同时 Godot（如 N=2～4），其余「排队试玩」；代码/对话不排队或分队列 | 无学生机 Godot 也能上；实现相对可控 | 试玩体验差、课上易堵；与「全屏置顶」运维冲突 | 无分散 PC、只有薄终端时 |
| **S4. Agent 全局并发帽 + 排队** | `max_concurrent_agents`（如 4～8）+ 公平队列；会话数可到 70 | 保护 LLM 与磁盘；70 人「在线」不等于 70 路同时改 | 高峰等待长，需 UI 排队进度 | **任何方案都应叠加** |
| **S5. 多机 API 水平扩展** | 多 FastAPI + 共享 Redis + 共享 NAS workspace + PostgreSQL 学情 | 真扩展 C70-Agent | 运维与一致性复杂，超出现网；workspace 锁/亲和困难 | 二期、跨校级 |
| **S6. 错峰 / 分班场次** | 软件帽 + 教务 35+35 两场 | 零研发风险 | 依赖排课，不是纯技术解 | 与 S2/S4 组合的运营兜底 |

#### 推荐（服务器教学部署 · 已拍板）

**采用「S2-路B + S4」**（教学机房更现实、落地更快）：

1. **一台（或一小集群）服务器**承担：Kiosk、API、Redis 会话、`workspace` 权威目录、学情 SQLite、LLM 出口。  
2. **`max_sessions` / 在线用户 ≥70**（C70-Web）；单用户 1 个活跃创作会话。  
3. **`max_concurrent_agents` 单独设帽**（建议首版 4～8），超额排队并显示中文进度。  
4. **试玩默认 S2 · 路 B（共享盘 / 映射盘）**：  
   - `workspace` 经 SMB/NAS 共享；学生机镜像固定映射盘符；  
   - 每机预装 Godot 4.6；点试玩 = 本机打开映射路径下**本人 session 目录**（可配极简启动脚本）；  
   - **首版不做路 A**（打包下载 + 完整薄客户端）；路 A 仅作无共享盘时的远期备选。  
5. 服务器**不为** 70 人在本机拉起 Godot。  
6. 验收：C70-Web + S4 必测；C70-Play 机房抽样「映射盘 + 本地 Godot」；不用「服务器开 70 个 Godot」。

| | 路 A（下载再玩） | **路 B（共享盘 · 已选）** |
|--|------------------|---------------------------|
| 教学机房 | 要装助手、做同步 | **镜像 + 映射 + Godot，IT 一次配齐** |
| 首版 | 不做 | **做** |

> 与 RL-1/RL-2 一致：改动只落各自临时工作区；共享盘按用户/会话隔离，禁止可读他人目录。

### 8.4 可维护性

- 教学注解表与问卷 schema 版本化（`schema_version`）。  
- 与 7.19 Agent 主线解耦：F1/F2/F3/F5/F6 失败不得破坏「无教学扩展」的展厅模式启动。

### 8.5 无障碍与设备

- 键鼠机房优先；触控一体机星星与文件树仍可点。  
- 代码色盲友好：Diff 同时用 +/- 与色条。
