## 0. 一句话

有 `LLM_API_KEY` 时，从**第一轮**起就是 **LLM 多工具循环**（对标 Claude Code「全开」）：整句理解 → **开放读盘定位** → 在会话副本自由更新/修复 → 门禁验收；**禁止** catalog 点名快车道顶替实现；**禁止**为单个现象堆 Intent if 补丁。最大化 LLM：提示只软建议，门禁只验收。回主页只 harvest **已验证有效**的经验；对话仍反映未修复/未实装的，**不准**写成有效 Learned Skill。社区预制经验经人工策展后，按七品类真实代码微调，落成可参考 Skill（非运行时爬虫）。

## 1. 产品目标与边界

### 1.1 目标体验

| 维度 | 要求 |
|------|------|
| 对话 | 像大模型助手：听全句、拆 goals、诚实反馈、失败继续改 |
| 施工 | 像 Claude Code：多工具、读再写、自检、不空话交差 |
| 范围 | 七品类会话副本（shmup / platformer / parkour / survivor / fighting / racing / pingpong） |
| 素材 | Catalog / 桥 API / Learned Skill / Reference Skill = **可选材料**，不是入口、不是天花板 |

### 1.2 硬边界（不变）

- 禁止改 `templates/{genre}/core` 玩法冻结源；可改 `workspace/{session}/` 与 `_edu`/契约/Agent  
- 幻想 API 禁；声称 ⊆ 磁盘；触屏 `how_to_play`；玩家健康（HF-10）；Godot dry-run；手动重开  
- 无联机/存档/内购/广告；GDScript 禁 OS.execute / HTTP 等  
- 面向 14 岁以下；操作 ≤ 3 键  

### 1.3 非目标（本总纲阶段）

- 运行时自动爬全网写盘（合规与质量不可控）  
- 自动晋升官方 `templates` catalog  
- 恢复有 Key 的 catalog express

## 3. 有 Key 运行时形态（对标 Claude Code 全开）

```text
用户原话（整句）
  → understanding + goals[]          # 强制覆盖子句
  → 【第 1 轮起】多工具循环：
       diagnose_workspace / list_dir / read_file
       （可选）search_learned_skills / 读 reference_skills
       write_file / enable_catalog_skill（仅 goals 允许时）
       validate_gdscript / self_check / dry_run / 玩家健康
       emit_progress …
  → done（summary 覆盖全部 goals）或 salvage（诚实 partial，不上锁）
  → UI → 用户手动重开试玩
  → 不满意：「没生效」/ 新原话 → 同一 Agent 循环继续（不降级 express）
```

### 3.1 工具与材料优先级

1. **会话磁盘实况**（读盘结果）+ **本局近期写入清单**（session log）  
2. **品类 playbook / Contract**（`genre_context`）  
3. **`data/reference_skills/`**（策展参考，只读提示）  
4. **`data/learned_skills/`**（经有效 harvest 的跨局经验）  
5. **Catalog / 桥 API**（可选实现手段，非强制）

### 3.2 总原则 · 开放读盘（G11）

1. **统一循环**：新需求与「没生效/颜色不对/太快」等反馈，共用同一套多工具施工；不换弱引擎、不换窄剧本。  
2. **定位靠磁盘**：优先读本局近期写入文件与 diagnose；用用户原话做验收标准做对照（含「谁开了状态、谁没关」）。  
3. **提示软、门禁硬**：Intent/Catalog/playbook = 建议；声称⊆磁盘、玩家健康、dry-run、条件落地 = 验收。  
4. **禁补丁堆叠**：不为「球色」「脚步」等单点加 Intent 分支；缺陷修在 Agent 工作法本身。  
5. **最大化 LLM**：少硬禁令、多上下文（改动清单、磁盘、原话）；salvage 诚实且推动继续读盘写盘。

热更新施工：[`7.19_AI改游戏智能体_HF-11_开放读盘智能体_热更新.md`](./7.19_AI改游戏智能体_HF-11_开放读盘智能体_热更新.md)

### 3.3 与「秒哒切片」关系

秒哒三件套解决「快车道吞需求」；本总纲在其上锁定：**LLM 全开从第一轮开始**、**放宽轮次**、**开放读盘（G11）**、**有效 harvest**、**Reference Skill 策展**。

### 3.4 安全读写闭环（G12 · 自动闭环已落地）

2026-07-19 Live 复查曾暴露整写、截断与语义漂移；当前已按 G12 落地：

1. 已有大文件默认 `replace_text/apply_patch`，整写只用于新文件或经批准的重构；
2. read 结果带 offset/eof/hash，工具 observation 不做无标记硬切；
3. 每次代码 mutation 后运行 Godot 校验，失败恢复本动作快照；最终 `gate_passed=false` 不交成功 `sandbox_files`；
4. 比较本轮前后函数/信号/export/onready/节点/关键链，阻止非目标删除；
5. 有 Key 的确定性专用能力（含 shmup drop-loot）改为 **LLM 可调用工具**，不在首轮 LLM 前 return；
6. 自动闭环基线 **272 passed, 2 skipped**；生产入口离线探针 **9/9**；HF-13 七品类×三任务 Live 首轮自动层已收口（`e2e_7_19_live_three_tasks.py`）；**人工可用性测试基本通过**（HF-12 §9.3）。

## 4. 七品类统一能力

| 能力 | 说明 |
|------|------|
| 听懂 | 整句 → goals；点名 catalog 口语也不短路 |
| 抄真游戏 | 复制进 workspace 的是真实模板结构；改前读对应 `.gd`/`.tscn` |
| 自由完成 | 新机制写会话 `core/scenes/config/ai_sandbox`；不要求先命中预制 |
| 可感 | 触屏按钮 / how_to_play；玩家可见可控（HF-10） |
| 诚实 | 门禁不过或条件未落地 → 不说「已全部完成」 |

品类接线权威仍以 `genre_context._GENRE_PLAYBOOK` + Reference Skill 为准（例：乒乓操控体是 `PlayerPaddle` 不是 `Player`）。

## 5. Skill 体系（三类，勿混）

| 类型 | 路径 | 何时入库 | Agent 用法 |
|------|------|----------|------------|
| **Catalog** | 契约 / optional_skills | 人工维护模板 | 仅参考或 goals 明确「只要开关」时 enable |
| **Learned** | `data/learned_skills/` | **仅有效会话** harvest | `search_learned_skills` Top-K |
| **Reference** | `data/reference_skills/` | 策展（社区经验×本仓库微调） | 读盘式参考；**不是** express 入口 |

### 5.1 有效 Learned Skill 硬条件（G8）

同时满足才可 `safety=ok` 入库/合并 success：

1. 本局存在成功 nl-patch 日志；且  
2. 声称能力有磁盘证据（sandbox_files / snippet 质量过关）；且  
3. **终局对话不处于「未修复/未实装/没生效」否定态**（含：最后一轮 bugfix 未过门禁、用户明确没生效且未再成功交付、salvage 且 playability 可疑）；且  
4. 无幻想 API / 暴力违规。

否则：可写 experience 备查（可选），**不得**提升 `success_count` / 不得新建有效 index 行。

> **已落地**：`session_is_negative_for_harvest` 拦截终局否定态；否定会话可记 experience，不入库有效 Skill。

### 5.2 Reference Skill 策展原则

- 来源：公开 Godot 4 Agent Skill / MCP 实践 / 风格指南（见 `data/reference_skills/SOURCES.md`）  
- 必须 **对照本仓库路径与节点** 改写（禁止泛泛「做一个 Player」）  
- 标注 `verified_against_templates: true` 仅表示架构对齐，**不**表示某次用户局已试玩通过  
- 禁止把未接线 catalog 吹成「一键可玩」

## 6. 回主页 / release

```text
用户回主页 / release
  → 判定本局是否「有效交付」
  → 有效：harvest → Learned Skill
  → 无效：跳过有效 Skill（可记 rejected / skipped）

```

## 8. 工程参数（已拍板 · 2026-07-19）

| # | 议题 | **锁定值** |
|---|------|------------|
| Q1 | `max_rounds` | **16**（可用环境变量 `AGENT_MAX_ROUNDS` 覆盖） |
| Q2 | 软续杯 | 首段 16 轮内有进展（写盘/enable）→ **再 +16 一次**（同请求硬顶 32） |
| Q3 | **墙钟**超时 | **360s**（见下方释义）→ 软停 + 诚实 partial |
| Q4 | Reference 注入 | Phase A：启动摘要 + 工具 `read_reference_skill` |
| Q5 | 目录 | Learned / Reference **分离** |
| Q6 | Harvest 否定态 | 没生效后无过门禁 / salvage+playability_suspect / user_rejected → **不入库有效 Skill** |
| Q7 | 脏 Learned | 检索降权 `verified_gate!=true` 与高 `fail_count` |
| Q8 | drop-loot | **保留专用实现能力**；改为首轮 LLM 可调用工具，**不保留 pre-LLM return**；≠ catalog express |
| Q9 | 社区采集 | 白名单策展；禁止运行时爬未知站 |
| Q10 | 两阶段固定工作流 | **废弃** |

### 墙钟是什么？

**墙钟（wall-clock）** = 从这次用户请求开始，到强制收工，**真实经过的秒数**（看墙上的钟），与「跑了几轮 LLM」无关。

- `max_rounds=16`：最多思考/工具 **16 轮**（还可软续杯）  
- `墙钟=360s`：不管还剩几轮，**满 6 分钟**就诚实 partial 停下来，避免展厅一张请求无限卡死  

二者同时生效，谁先碰到谁停。可用环境变量 `AGENT_WALL_CLOCK_SEC` 覆盖。
