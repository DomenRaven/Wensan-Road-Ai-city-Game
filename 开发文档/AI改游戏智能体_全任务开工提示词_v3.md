## 提示词正文（复制从此处开始）

```
你是本仓库「AI 改游戏智能体」实现 Agent。当前唯一主线：把「用户短对话改会话游戏副本」做成品类无关、可感知可玩的管道。

## 权威文档（必须先读）
1. 开发文档/AI改游戏智能体需求_v1.md （v1.2，尤其 §4 通用落地工作流）
2. 开发文档/AI改游戏智能体_施工规范手册_v1.md
3. 开发文档/AI改游戏智能体_文件映射表_v1.md
4. 开发文档/工作方向锁定_AI改游戏智能体_v1.md
5. 开发文档/AI改游戏智能体_根因分析与闭环改造_v1.md（背景）
6. .cursor/rules/godot-mini-game.mdc

非主线（模板引擎扩品类、秒哒爬虫、展陈彩排等）一律不做，除非阻塞本主线。

## 产品目标
用户在 B6/B7 说一句需求 → Agent 改 workspace/{session} → 三层落地（配置/代码/运行时接线）→ 触屏可点 → done 过门禁 → UI 展示说明 → 用户手动「现在重开游戏」→ 能玩到效果。

禁止：开环口头 done、幻想 API、只改 config 不开 runtime、只修某一品类特例冒充系统完成、自动重开掩盖未落地。

## 红线
- 禁止改 templates/{genre}/core/**
- 允许改 templates/_edu/**、config/agent_contracts/**、backend creative/agent 相关、kiosk nl-patch/wait、edu_workspace 注入
- Agent 运行时只写 workspace/{session}/
- 不自动 commit；不提交 .env

## 本阶段交付（P0-自主智能体）
按施工规范推进：
1. LLM 主导：诊断磁盘 → 读文件 → 选 Skill/契约 → 施工 → self_check → done
2. 意图路由仅建议，禁止硬绑「再开 catalog」冒充修复反馈
3. 工具：diagnose_workspace / self_check / refresh_ai_sandbox_bridge / patch_mouse_steer_guard
4. 产品真 bug 修 `_edu` 通用层，不堆品类 if
5. 单测 + 反馈类抽测（按钮不发射/E 可以等）
6. godot-mcp 抽测无 ERROR

## 验收口诀
配置有 · 代码通 · 接线活 · 触屏点 · 门禁过 · 手动重开

## 工作方式
- 先读映射表定位文件，再改；先契约/门禁，再桥，再 UI
- 改 _edu 或 edu_workspace 后提醒：旧会话需重新制作一局才注入
- 回复简洁：结论 → 改了什么 → 如何验
- 完成一项勾 todo；全部完成后对照需求 v1.2 验收表自检

开始：先读上述文档，列出差距与实施计划，再动手。
```
