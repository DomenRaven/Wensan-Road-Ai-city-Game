| 时段/主题 | 做了什么 | 关键落点 |
|-----------|----------|----------|

| 前端对话 | 同会话带历史；展示理解/拆解；故障可写 feedback；cache bust | `nl-patch-dialog.js?v=7.4-c09-25` |

| 单测对齐 | Agent-only 路径；sanitize 独立测；不再期望 `provider=llm` | `test_ai_sandbox` 等 · **70 passed**（不含 live） |
| 后端 | uvicorn 本机 `:8000` 健康 | `/health` ok |

### 已修用户可见假象（足迹要点）

1. 「没法启动」却答炸弹 → 续聊误判 + 主句拼接 how_to_play → 已收紧。  
2. 「人物消失」→「没找到能安全调整」→ Agent 失败降级旧 LLM 空改 → **已禁止该降级**。  
3. 触屏 how_to_play 过严导致故障局 done 失败 → 故障局软门禁。

### 3.2 降级策略（权威口径）

| 触发 | 行为 | 是否「LLM 做不到」 |
|------|------|-------------------|
| 无 `LLM_API_KEY` | `provider=stub` 本地规则 | 否 · 离线演示 |
| 有 Key · Agent 成功 | `provider=agent` | — |
| 有 Key · Agent 失败（门禁/HTTP/轮次） | 重试最多 2 次 → **诚实失败** `provider=agent` | 否 · 施工未过，非换弱引擎 |
| Intent D 幻想 API | 继续 Agent（C）用 GDScript | 否 |
| 写盘安全 / 技能白名单 | 拒写或过滤 | 安全门禁，非降级 |

**死代码**：`llm_patch._call_llm` 仍在文件中，**有 Key 时 `apply_nl_patch` 不再调用**。
