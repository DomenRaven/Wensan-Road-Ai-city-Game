## 一、结论（Executive Summary）

| 项 | 结论 |
|----|------|
| **推荐方案** | **A4 · 外置窗 + godot-zone 视觉对齐优化** |
| **是否真内嵌** | 否 — 采用文档定义的「等价效果」：外置 Godot 窗精确贴齐 `.godot-zone` 屏幕矩形，Kiosk 内 zone 与 OS 窗视觉一体 |
| **降级路径** | 保留 P3-3 全链路：`window_placed=false` → 状态卡手动指引，launch 不阻断 |
| **A1 不做** | A1 WASM iframe · A2 SetParent HWND · A3 截图推流 |
| **PoC** | 未新建独立 PoC — 现有 v1.1 栈即 A4 基线；本 Spike 以代码审阅 + E2E 实跑验证 |

**一句话**：展厅 P4 不宜切换引擎形态；在已验收的 P3-3 Win32 归位上抛光 zone/文案/横竖屏同步，风险最低且满足甲方「画面出现在引导区内」的观感目标。

## 三、候选方案评估

### 评分维度（1–5，5=最适合展厅 P4）

| 维度 | 权重 | 说明 |
|------|------|------|
| 交付风险 | 30% | 7.4 窗口期 · 七款冻结 · 触控 P4-B 并行 |
| 与 workspace 兼容 | 25% | 每 session 动态 copy + B5 patch + hooks |
| 横竖屏 1920×1080 / 1080×1920 | 15% | 已有 P3-2/P3-3 |
| B7 hooks / 触控 | 15% | `.edu_actions.jsonl` · `_edu` overlay |
| 真内嵌程度 | 15% | 甲方观感，非硬指标 |

### A1 · HTML5/WASM + iframe

| 项 | 评估 |
|----|------|
| 原理 | Godot Export Web → 静态 `.wasm`/`.pck` → Kiosk `<iframe>` 填入 `.godot-zone` |
| 优点 | 唯一「真 DOM 内嵌」；跨平台；无 Win32 |
| 缺点 | **导出链与 B 链冲突**：每次 generate 后 workspace 路径变，需 **按 session 增量导出**（7 品类 × 冻结模板 × touch overlay）；仓库 **无** `export_presets.cfg`；Godot 4.6 Web 包体大、冷启动慢；线程/扩展受限；与 v1.1/v1.0 展陈 P0「外置 exe」战略相反 |
| 工作量 | **高**（新 CI 导出任务、静态资源服务、七款回归） |
| 风险 | **高** — 易挡 P4-B 触控 deadline |
| 得分 | **1.8 / 5** |

**放弃理由**：动态 workspace + 七款 R2 冻结 + P4-B overlay 注入，使「launch 后 3s 内可玩」难以保证；6.24/6.26 已书面排除 iframe embed。

---

### A2 · Win32 SetParent（HWND 挂入浏览器）

| 项 | 评估 |
|----|------|
| 原理 | 取 Godot 顶层 HWND + 浏览器内容区 HWND → `SetParent` 子化 |
| 优点 | 仍跑原生 exe · 性能与 P3-3 相同 |
| 缺点 | Chrome/Edge **不支持**稳定 foreign HWND reparent（焦点、DWM、沙箱、全屏、多显示器 DPI）；需 **浏览器侧 Native 宿主** 或 CEF — 当前栈无；与 P3-3 `SetWindowPos` **重叠**且更 fragile；竖屏 resize/orientation 需同步两套坐标 |
| 工作量 | **中高**（实验性 Win32 + 前端宿主约定） |
| 风险 | **高** — 彩排偶发黑屏/焦点丢失 |
| 得分 | **2.0 / 5** |

**放弃理由**：P3-3 已用更简单的「同级顶层窗 + 坐标对齐」达到 90% 观感；SetParent 不增加可交付收益。

---

### A3 · SubViewport 截图/纹理推流

| 项 | 评估 |
|----|------|
| 原理 | Godot 内抓帧 → WebSocket/MJPEG → `<canvas>`/`<img>` 在 zone 内播放 |
| 优点 | 浏览器内显示像素；可绕过 HWND |
| 缺点 | **延迟** 50–200ms+，格斗/赛车/飞机 unacceptable；需改启动管线或 headless 分支 — **禁止改 `core/`**；编码 CPU 占用；触控需 **反向** 注入 Godot；七款输入模型各异 |
| 工作量 | **很高**（新服务 + 协议 + 前端播放器 + 输入回传） |
| 风险 | **很高** |
| 得分 | **1.2 / 5** |

**放弃理由**：K12 试玩要求即时反馈；与 P4-B 触控 overlay 架构重复且更慢。

---

### A4 · 外置窗 + godot-zone 视觉对齐（推荐）

| 项 | 评估 |
|----|------|
| 原理 | 延续 P3-3：`godot_zone_rect` → `place_by_pid`；Kiosk `.godot-zone` 虚线框与 OS 窗 **同矩形** |
| 优点 | **v1.1 已验收**（[`6.26_P3-3_验收记录`](./评审记录/6.26_P3-3_验收记录.md)）；E2E/pytest 齐全；hooks/overlay 零改动；降级路径现成；A1 仅改 kiosk 文案/样式 + 可选无边框窗/resize 监听 |
| 缺点 | 非真 embed；双窗口 Z-order 极端情况下 Godot 可能被挡（讲解员环境可控） |
| 工作量 | **低**（P4-A1 预估 0.5–1 窗） |
| 风险 | **低** |
| 得分 | **4.6 / 5** |

**选用理由**：满足 FRS §四「真内嵌或文档定义的等价效果」；与 7.4 总控「勿删 P3-3」一致；不阻塞 P4-B。

## 五、A4 等价效果定义（P4-A1 施工依据）

甲方用户故事：「画面出现在 Kiosk 页面右侧/下方引导区内」。

**A4 等价标准**（满足即视为 P4-A 收工）：

1. **几何对齐**：`window_placed=true` 时，Godot 客户区与 `godot_zone_rect` 偏差 ≤ **2px**（横屏）；竖屏与 Win32 下半屏一致（现有逻辑）。
2. **视觉一体**（P4-A1 抛光项）：
   - `window_placed=true` → zone 虚线改 **实线/浅蓝底** 或隐藏虚线，避免「空框」感；
   - B7 文案由「外置窗口」改为「游戏已加载在右侧/下方试玩区」；
   - 可选：Godot `--borderless` 或去标题栏，减少 OS  chrome 错位。
3. **动态同步**（可选 P4-A1）：`orientationchange` / resize 防抖后 **re-launch placement**（`already_running` + 新 rect，不杀进程）。
4. **降级不变**：`window_placed=false` → 保留 P3-3 手动指引 + launch 成功。

不涉及：`templates/core` · RECIPE · P4-B overlay 文件。

## 六、横/竖屏布局示意（Spike 截图替代 · 实机见 P3-3 验收）

> 正式像素截图在 P4-A1 收工时补拍；下列为 A4 对齐逻辑的可视化证据（与 [`6.26_P3-3_验收记录`](./评审记录/6.26_P3-3_验收记录.md) 人工验收一致）。

### 6.1 横屏 1920×1080

```text
┌────────────────────────── Kiosk 浏览器 ──────────────────────────┐
│ 顶栏 · B7 试玩                                                    │
├──────────────────────────────┬───────────────────────────────────┤
│  左栏 45~55%                  │  .godot-zone（虚线 → A1 改实线）   │
│  代码高亮 · 演示钮             │  ╔═══════════════════════════════╗ │
│                              │  ║  OS Godot 窗（place_by_pid）   ║ │
│                              │  ║  与 zone 同屏幕矩形            ║ │
│                              │  ╚═══════════════════════════════╝ │
└──────────────────────────────┴───────────────────────────────────┘
         godot_zone_rect.x ≈ 960 · w ≈ 960 · h ≈ 1080
```

**数据流**：`EduOrientation.getViewportPayload()` → `POST /play/launch` → `resolve_placement_rect(landscape)` → `place_by_pid`.

### 6.2 竖屏 1080×1920

```text
┌──────────── Kiosk 浏览器 ────────────┐
│ 顶栏（折行）                          │
├──────────────────────────────────────┤
│  上栏 ~42% · 代码/演示                │
├──────────────────────────────────────┤
│  .godot-zone / 状态卡                 │
│  ┌────────────────────────────────┐  │
│  │ OS Godot 窗 · 主显示器下半屏    │  │
│  │ get_monitor_bottom_half_rect    │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

**数据流**：portrait → `MonitorFromPoint(anchor)` → 下半屏 rect（不依赖 `screen.width` 浏览器值）。
