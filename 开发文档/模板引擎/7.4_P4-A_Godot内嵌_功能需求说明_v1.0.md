## 一、用户故事

作为展厅参观者，我希望试玩时 **Godot 画面出现在 Kiosk 页面右侧/下方的引导区内**，而不是单独的 OS 窗口，视觉更一体；若内嵌失败，仍能像 v1.1 一样用外置窗试玩。

---

## 二、现状（v1.1 · 勿在未评估前删除）

| 组件 | 实现 |
|------|------|
| 启动 | `godot_launcher.py` subprocess GUI exe |
| 归位 | `godot_window_layout.py` Win32 `place_by_pid` |
| 前端 | `client_viewport` + `.godot-zone` 虚线引导区 |
| 横屏 | `godot_zone_rect` 屏幕绝对坐标 |
| 竖屏 | 主显示器下半屏 |

---

## 三、候选方案（Spike 必评）

| 代号 | 方案 | 关键风险 |
|------|------|----------|
| A1 | HTML5/WASM + iframe | 导出链 · workspace 动态 copy |
| A2 | Win32 SetParent HWND 入浏览器 | Chrome/Edge 不稳定 · 与 P3-3 重叠 |
| A3 | SubViewport 截图/纹理推流 | 延迟 · 工作量 |
| A4 | 外置窗 + zone 视觉对齐优化 | 非真内嵌 · 风险最低 |

**Spike 产出**：[`7.4_P4-A0_Godot内嵌Spike结论_v1.0.md`](./7.4_P4-A0_Godot内嵌Spike结论_v1.0.md)（A0 窗新建）

---

## 四、功能要求（实现窗 P4-A1）

| # | 要求 |
|---|------|
| 1 | 试玩画面在 `layout.godot_zone` 对应区域可见（真内嵌或文档定义的等价效果） |
| 2 | 横屏 1920×1080 · 竖屏 1080×1920 均可用 |
| 3 | 内嵌失败 **降级** 至 P3-3 外置窗（`window_placed` + 状态卡指引） |
| 4 | B7 launch 流程不阻断；hooks 轮询不变 |
| 5 | 现有 E2E 通过或明确迁移为新脚本 |

---

## 五、涉及路径

| 路径 | 职责 |
|------|------|
| `backend/app/services/godot_launcher.py` | 启动元数据 |
| `backend/app/services/godot_window_layout.py` | Win32 布局（A2/A4） |
| `backend/app/routers/play.py` | launch 响应字段 |
| `kiosk/edu/edu-wizard.js` | godot-zone 容器 |
| `kiosk/edu/edu-styles.css` | zone 样式 |
| `kiosk/edu/layout/orientation.js` | 横竖屏 rect 同步 |
| `config/kiosk_edu_spec.json` | `layout.godot_zone` |
