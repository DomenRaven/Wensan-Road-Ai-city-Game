## 四、本阶段三项任务（总控派窗依据）

### P4-A · Godot 窗口内嵌（探索）

**甲方意图**：试玩时 Godot 画面出现在 Kiosk 页面内（`godot-zone` 区域），而非独立 OS 窗口。

**当前实现（勿在未评估前删除）**

- 外置进程：`godot_launcher.py` 启动 GUI exe
- 浏览器侧：`client_viewport` + Win32 `place_by_pid` 贴屏幕右半/下半
- Kiosk：`kiosk/edu/` 内 `.godot-zone` 虚线引导区（非真实 embed）

**可行方向（需 Spike 窗口选型，总控先派 1 个调研子窗）**

| 方案 | 说明 | 风险 |
|------|------|------|
| A1 HTML5/WASM 导出 | Godot Export Web · iframe 嵌入 zone | 导出链长 · 与 workspace 动态 copy 难结合 · v1.1 曾排除 |
| A2 Win32 HWND 嵌入浏览器 | `SetParent` 将 Godot HWND 挂到浏览器容器 | 仅 Windows · Chrome/Edge 行为不稳定 · 与现有 P3-3 重叠 |
| A3 进程内 SubViewport 截图流 | 极低帧率纹理推前端 | 延迟高 · 工作量大 |
| A4 保持外置窗 + 视觉对齐优化 | 延续 P3-3，仅美化 zone 边框/同步 | 非真内嵌，但风险最低 |

**涉及路径（选型后）**

- `backend/app/services/godot_launcher.py` · `play.py`
- `kiosk/edu/edu-wizard.js` · `edu-styles.css` · `layout/orientation.js`
- `config/kiosk_edu_spec.json` → `layout.godot_zone`

**验收草案**

- [ ] Spike 文档：选型结论 + 放弃理由
- [ ] 横/竖屏各 1 张截图：内嵌或对齐效果
- [ ] 现有 `e2e_p3_godot_window_layout.py` 通过或明确迁移为新 E2E

### P4-B · 七款全触控（正式落地硬需求）

**甲方意图**：落地环境为 **触摸屏**；无物理键盘时 **全部 7 款可正常游玩**。

| 类型 | 品类 | 期望操控 | 当前实现 | 缺口 |
|------|------|----------|----------|------|
| **虚拟键** | platformer 横版闯关 | 屏幕按钮：← → 跳 | 仅 `move_left/right/jump` 键盘 | ❌ 无 overlay |
| **虚拟键** | fighting 横版格斗 | 方向 + 轻拳/重拳/格挡/大招 | `fighting_touch_overlay.gd`（workspace 注入） | ⚠️ 需触摸屏实机验收 · 仅 P1 |
| **虚拟键** | survivor 割草生存 | 移动 + 朝向/射击 | WASD 移动 + **鼠标点击**瞄准 | ❌ 需虚拟摇杆或拖移 |
| **虚拟键** | parkour 跑酷 | 跳 · 滑铲 | `jump` / `skill` 键盘 | ❌ 无 overlay |
| **滑动** | pingpong 乒乓球 | 上下滑控制球拍 | 方向键 `move_up/down` | ❌ 需 Y 轴 drag/swipe |
| **滑动** | shmup 街机射击 | 左右滑移动 + 自动开火 | **鼠标 X 跟随**（`player_ship.gd`） | ⚠️ 触屏需 drag，非 swipe 语义 |
| **滑动** | racing 欢乐赛车 | 左右滑转向 | `steer_left/right` 键盘 | ❌ 需 drag 转向 |

**推荐实现策略（与 fighting 对齐）**

1. 新建 `templates/_edu/{slug}_touch_overlay.gd`（**勿改 `core/`**）
2. 在 `backend/app/services/edu_workspace.py` 按品类 patch 进 `main.tscn`（仿 fighting）
3. 虚拟键 ≥ **48×48 px** · 半透明 · 不挡关键画面
4. 滑动类：在 overlay 或 `CanvasLayer` 监听 `InputEventScreenDrag` / `InputEventMouseMotion`，映射到现有 Input Action
5. **单次会话只改一个品类模板目录**（Cursor 规则）
6. 每品类改完：`freeze_*_snapshot.py write/verify`（若该品类已冻结需先解冻）

**操作上限**：面向 14 岁以下 · **≤3 个主要操作**（现有规则）

**验收草案（每款）**

- [ ] 1080×1920 竖屏触屏 · 无键盘 · 完成 1 局/1 分钟可玩
- [ ] B7 演示钮 + hooks 高亮仍可用
- [ ] `e2e_b_edu_batch.py` 对应 slug PASS
- [ ] 人工记录：误触率 · 按钮可达性

**建议派窗顺序（可并行 2 窗，但每窗仅 1 slug）**

```text
B1 platformer（基线模板）
B2 parkour · survivor（虚拟键同类）
B3 fighting（验收+抛光，已有 overlay）
B4 pingpong · shmup · racing（滑动类）
B5 七款联调 + A 链 S9 快玩触控补验
```
